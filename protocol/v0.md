# Vivateria protocol v0

This is the M1 local human client wire contract, not the Agent API. One complete
message occupies one WebSocket binary frame. There is no text/JSON form, frame
length prefix, compression, or transport implementation in M1-04.

All multi-byte integers use little-endian byte order. Integers are exact: `u8`,
`u16`, `u32`, `u64`, signed two's-complement `i8` and `i64`. Every fixed-point
component is the raw signed `i64` bits of `Fx` Q32.32 (real value raw / 2^32).
Never convert a raw component through a float while decoding or encoding. A
renderer may separately derive visual floats after decoding. Godot's signed
64-bit `int` represents unsigned 64-bit fields by the same bit pattern (for
example `u64::MAX` is `-1`); hashes/seeds must preserve those bits.

## Common header

| Offset | Bytes | Field | Value |
|---|---|---|---|
| 0 | 4 | magic | ASCII `VIVP` (`56 49 56 50`) |
| 4 | 1 | wire_version | `u8`, exactly 0 |
| 5 | 1 | message_type | 1 through 5 below |
| 6 | variable | payload | Exactly the selected layout; no trailing bytes |

Maximum frame size is 4,194,304 bytes. Each entity/upsert/removal collection
permits 0 through 65,536 items. Reject larger counts before allocating, and
check the frame contains the advertised bytes before reserving collection
storage. A frame with a supported header and incomplete payload is truncated.
An unknown wire version or message tag is rejected, never guessed or skipped.

## Payloads (fields in wire order)

### 1: ClientHello (client to server)

| Frame offset | Bytes | Field | Encoding / meaning |
|---|---|---|---|
| 6 | 2 | protocol_version | u16; requested application protocol, v0 clients send 0 |
| 8 | 2 | name_length | u16; UTF-8 byte length N, maximum 64 |
| 10 | N | player_name | Valid UTF-8 without U+0000; empty name allowed by codec |

Total frame length: `10 + N` bytes (10 through 74).

Wire decoding preserves any `protocol_version`; accepting an unsupported
application version is a future handshake policy decision. This is distinct
from the always-validated header wire version. The limit counts UTF-8 bytes,
not characters. U+0000 (a zero byte) is rejected because Godot 4.7.2 strings
cannot preserve it. Other valid UTF-8, including a leading U+FEFF/BOM, is
preserved. No NUL terminator or Unicode normalization is applied.

### 2: ServerWelcome (server to client)

| Frame offset | Bytes | Field | Encoding / meaning |
|---|---|---|---|
| 6 | 4 | player_id | u32; connection's assigned player identity |
| 10 | 4 | tick_hz | u32; simulation rate, current server uses 20 |
| 14 | 8 | seed | u64; world seed |
| 22 | 8 | tick | u64; current simulation tick |

Total frame length: exactly 30 bytes.

The codec preserves the entire numeric range. Handshake policy checks such as
the expected tick rate belong to the transport/session implementation.

### 3: Input (client to server)

| Frame offset | Bytes | Field | Encoding / meaning |
|---|---|---|---|
| 6 | 8 | tick | u64; tick requested for the input |
| 14 | 1 | move_x | i8; exactly -1, 0, or 1 |
| 15 | 1 | move_y | i8; exactly -1, 0, or 1 |

Total frame length: exactly 16 bytes.

Reject out-of-range movement; do not clamp at this boundary. Identity is
derived from the connection and is never sent in Input. Tick acceptance,
late-input policy and rate limiting belong to M1-05 or subsequent server work.
No stage advancement, editor/evolution or alliance action appears here.

### 4: Snapshot (server to client)

| Frame offset | Bytes | Field | Encoding / meaning |
|---|---|---|---|
| 6 | 8 | tick | u64; tick of the full visible state |
| 14 | 8 | state_hash | u64; authoritative full simulation hash at this tick |
| 22 | 4 | entity_count | u32; count E of following records |
| 26 | 49 × E | entities | Entity records below; record i starts at `26 + 49 × i` |

Total frame length: `26 + 49 × E` bytes. Record indices run from 0 through E-1.

Entity lists are strictly ascending by ID (no duplicates). Encoders sort local
lists; decoders reject duplicates and descending IDs. Empty lists are valid.
The simulation hash includes hidden RNG state and cannot be recomputed from
the visible entities alone. A snapshot is not a persistence/replay save file.

### Entity record (49 bytes)

| Record offset | Bytes | Field | Encoding |
|---|---|---|---|
| 0 | 4 | id | u32 |
| 4 | 1 | has_owner | u8, exactly 0 or 1 |
| 5 | 4 | owner_id | u32; must be 0 when has_owner is 0 |
| 9 | 8 | pos_x | raw i64 Q32.32 |
| 17 | 8 | pos_y | raw i64 Q32.32 |
| 25 | 8 | vel_x | raw i64 Q32.32 |
| 33 | 8 | vel_y | raw i64 Q32.32 |
| 41 | 8 | energy | raw i64 Q32.32 |

`has_owner=1, owner_id=0` is a valid owner. `has_owner=0` maps to Rust `None`
and Godot `null`. Raw fields accept the complete `i64` range; physical bounds
are simulation policy, not codec policy.

### 5: Delta (server to client)

| Frame offset | Bytes | Field | Encoding / meaning |
|---|---|---|---|
| 6 | 8 | base_tick | u64; state tick to which this delta applies |
| 14 | 8 | tick | u64; state tick after applying the delta |
| 22 | 8 | state_hash | u64; authoritative full simulation hash at tick |
| 30 | 4 | upsert_count | u32; count U of following complete records |
| 34 | 49 × U | upserts | Insert or fully replace each entity; record i starts at `34 + 49 × i` |
| 34 + 49 × U | 4 | removed_count | u32; count R of following removed IDs |
| 38 + 49 × U | 4 × R | removed | u32 IDs to remove; ID j starts at `38 + 49 × U + 4 × j` |

Total frame length: `38 + 49 × U + 4 × R` bytes. Upsert indices run from 0
through U-1; removed indices run from 0 through R-1.

Upserts and removed IDs are each strictly ascending, unique lists. An ID may
not occur in both lists. Encoders sort both lists and reject duplicates or
overlap. Empty lists are valid. Apply only to matching `base_tick`; a mismatch
requires a full snapshot through future session policy. The codec does not
apply deltas, compare ticks or schedule resynchronization.

## Validation and API

Rust `Message::decode(&[u8]) -> Result<Message, DecodeError>` is total for
untrusted frames: it returns errors without panicking or reading out of bounds.
Errors cover bad magic, unsupported wire version, unknown message type,
truncation, trailing bytes, invalid UTF-8, U+0000 in a player name
(`NulInPlayerName`), name/count/frame limits, movement
range, owner tag/absent-owner value, unordered/duplicate IDs and delta overlap.
Validation proceeds from the header through fields in wire order; when multiple
conditions fail, the first detected error is returned.

Rust `Message::encode() -> Vec<u8>` canonicalizes lists and requires a valid
local message (it panics on invalid locally constructed fields).
`try_encode() -> Result<Vec<u8>, DecodeError>` provides non-panicking validation
for local messages. Neither API alters simulation behavior. Conversion helpers
map `Entity` to/from exact raw fields, `World` to a `Snapshot`, and `Input` to a
`PlayerInput` using the connection-assigned player ID.

Both codecs consume the same checked-in [golden binary fixtures](fixtures/README.md).
Rust tests assert independent expected bytes, all-message round trips, every
truncated fixture prefix and malformed field cases. Godot tests decode the same
bytes and byte-compare ClientHello/Input encoding.
